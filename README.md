Интеграция читает телеметрию преобразователя, показывает расшифрованное
состояние и аварии и позволяет управлять насосом и редактировать параметры
прибора прямо из Home Assistant — вместо ручного перечисления регистров в
YAML-конфиге `modbus`.

Преобразователи — [ЭРМАНДЖАЙЗЕР](https://www.ermangizer.ru/) (российские
частотные преобразователи для насосов и автополива).

## Установка

### Через Marketplace (Home Assistant 2026.11 и новее)

1. Settings → Devices & Services → ⋮ (или Marketplace в боковом меню).
2. Добавить пользовательский репозиторий: `akalagov/ha-ermangizer`,
   категория **Integration**.
3. Найти «Ermangizer pump controllers» и установить. Обновления приходят
   штатно через Settings → Updates.

### Вручную

Скачать `ha-ermangizer-<версия>.zip` со [страницы выпусков](https://github.com/akalagov/ha-ermangizer/releases) и
распаковать в конфигурационный каталог Home Assistant — `custom_components/`
уже лежит внутри архива, так что распаковывать нужно в его корень, а не внутрь
существующего `custom_components/`. После этого перезапустить Home Assistant.

Проверить, что получилось, можно так: файл `custom_components/ermangizer/manifest.json`
должен существовать, а `custom_components/ermangizer/ermangizer/` — **нет**
(типичная ошибка двойной вложенности, при которой интеграция не появится в
списке).

Во всех случаях зависимость `tmodbus` Home Assistant установит сам при первой
настройке интеграции — при отсутствии интернета на хосте HA её нужно поставить
заранее.

## Настройка

Одна запись интеграции = **одна физическая шина**, а не одно устройство.
Контроллеры добавляются на следующем шаге тем же мастером и хранятся как
subentry; добавить насос позже можно кнопкой «Добавить устройство» в карточке
интеграции, не настраивая подключение заново.

| Шаг | Что запрашивается |
| --- | --- |
| 1 | Тип подключения: Modbus TCP, RTU поверх TCP или локальный serial |
| 2 | Параметры шины: хост и порт либо serial-настройки, пауза между запросами |
| 3 | Контроллер: имя, адрес Modbus, карта регистров, интервалы опроса, уровень доступа |

### Типы подключения

- **Modbus TCP** — шлюз сам говорит по Modbus и сам оборачивает PDU в MBAP.
  Так работает многопортовый RS-485—Ethernet шлюз, когда его порт настроен как
  «Modbus TCP». Скорость RS-485 задаётся на шлюзе и Home Assistant её не видит;
  на каждый последовательный порт — своя запись интеграции.
- **RTU поверх TCP** — прозрачный мост serial↔TCP: кадры RTU с CRC
  пересылаются как есть (Elfin EW11, USR-W610/TCP232 и подобные).
- **Serial** — USB-RS485-адаптер, воткнутый в машину с Home Assistant.

### Карта регистров

Производитель выпускает прошивки с двумя несовместимыми картами регистров:

| Ключ | Что это |
| --- | --- |
| `auto` (по умолчанию) | Прочитать по одному регистру состояния из каждой карты и выбрать ту, что ответила |
| `legacy_220_01` | ER-G-220-01(02), «Протокол связи MODBUS»: телеметрия в нижнем блоке, слово состояния в 1024 |
| `modern_220_02_05` | ER-G-220-02 / ERG-220-05 (2025): телеметрия от 2000, параметры меню в 1000+NNN |

Автоопределение выбирает первую ответившую карту. Если контроллер отвечает на
оба адреса, карту стоит указать вручную.

## Что даёт интеграция

| Платформа | Содержимое |
| --- | --- |
| `sensor` | Телеметрия (частота, ток, напряжение, мощность, давление, температура), расшифрованное состояние, список аварий; для слова состояния и слова аварий — сырые значения отдельными сущностями |
| `binary_sensor` | Работает ли насос, есть ли авария; для legacy-карты — перегрузка двигателя |
| `switch` | Пуск и стоп насоса |
| `button` | Аварийный стоп, сброс аварии, сохранение/загрузка параметров из ПЗУ, дискретные выходы Y1/Y2 |
| `number` | Числовые параметры (уставки, частоты, временные задержки, коэффициенты ПИ) |
| `select` | Параметры-перечисления: режим работы, способ задания уставки и т. п. |

Набор `number`/`select` зависит от **уровня доступа** — он повторяет уровни
доступа P099 самого прибора. По умолчанию «общие параметры»; «расширенные» и
«заводские» добавляют параметры, меняющие режим работы насоса.

### Управление

Катушки пуска и останова — это **импульсы команды**, а не хранимое состояние,
поэтому положение switch читается из слова состояния, а не из катушки: после
пуска по давлению или по сигналу внешнего реле switch пойдёт за реальным
состоянием насоса, а не останется «включённым».

Значение параметра пишется в регистр сразу, прибор применяет его немедленно.
Параметры, влияющие на режим работы, помечены атрибутом `warning` — он виден в
карточке сущности до того, как значение изменят.

## Давление: bar без пересчёта

В документации производителя давление в **кгс/см²**, и регистры масштабированы
под эту единицу (сырое 275 = 2,75 кгс/см²). Интеграция подписывает эти значения
`bar` **без пересчёта**: число в Home Assistant, число на дисплее прибора и
число в регистре совпадают.

Это осознанное допущение. 1 кгс/см² = 0,980665 bar, то есть показания и уставки
завышены примерно на 2 %. Пересчёт сделал бы уставку «3 bar» равной 3,06 на
панели прибора, и согласовывать её с насосом пришлось бы вручную; совпадение с
дисплеем важнее точности единицы. Если нужен физически точный bar — создайте
шаблон-сенсор с множителем 0,980665.

## Опрос

Шина RS-485 полудуплексная, поэтому опрос разделён:

- **слово состояния** читается каждый цикл (по нему работают автоматизации),
- **аналоговая телеметрия и параметры** — раз в `slow_poll_interval`.

Соседние регистры объединяются в одно чтение, лишние регистры между ними
читаются, но их количество ограничено тестом: лишний запрос на шине стоит
дороже нескольких прочитанных впустую регистров.

## Диагностика

`scripts/probe_ermangizer.py` — автономный скрипт разведки регистров. Он не
требует Home Assistant и полезен, когда надо понять, что реально отдаёт
контроллер (например, перед тем как править карту регистров):

```bash
python3 scripts/probe_ermangizer.py --transport rtu_over_tcp --host HOST --port PORT --unit-id 8
python3 scripts/probe_ermangizer.py --transport tcp --host HOST --port 502 --unit-id 1
python3 scripts/probe_ermangizer.py --transport serial --device /dev/ttyUSB0 --unit-id 1 --baudrate 9600
```

Скрипт делает **только чтения** (FC03/FC04) и ничего не пишет, поэтому его
можно смело запускать на работающем насосе. Он печатает содержимое блоков
регистров и одновременно расшифровывает слово состояния по обеим картам —
какая из них даёт осмысленный ответ, та и ваша.

## Тесты

```bash
pip install -r requirements-dev.txt
python3 -m pytest
```

Тесты делятся на две группы. Юнит-тесты проверяют таблицы регистров,
масштабы, декодирование слова состояния и аварий, grouping чтений и CRC-кадры,
сверенные с примерами из документации производителя. Сквозные поднимают
настоящий Home Assistant и фейковое Modbus TCP устройство и проверяют, что
запись создаётся, сущности регистрируются, значения декодируются, а пуск,
стоп и запись параметра доходят до устройства.

## Известные ограничения

- История аварий (регистры от 3000) читается по запросу, но не выведена в
  сущности: для неё нет места в модели данных Home Assistant, кроме сенсора со
  списком.
- Параметры с плавающей точкой в формате IEEE-754 (несколько заводских
  параметров) отображаются как целые: документация не приводит для них
  масштаб.
- Уровни доступа выше «расширенного» показывают заводские параметры, которые
  производитель не рекомендует менять на работающей установке.
